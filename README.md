# Невинные сладости

Рабочий сайт: https://nevinnye-sladosti-orders.pages.dev/ . Репозиторий: https://github.com/dtemrieva-create/nevinnye-sladosti-orders . Статика HTML/CSS/JavaScript публикуется в Cloudflare Pages из public/, без команды сборки. При обновлении сохраняйте эти настройки.

Telegram: https://t.me/nevinnyesladosti_bot . MAX: https://max.ru/se14978156_bot . Supabase Free-проект: qdblduviiygaolwknuda. Управление раздельное: заявки Telegram обрабатываются в Telegram, заявки MAX — в MAX. Права владельца определяются проверенными ADMIN_CHAT_ID и MAX_ADMIN_CHAT_ID; остальные посетители видят только свои обращения.

## Каталог и материалы

В public/config.js подключён опубликованный CSV Google Таблицы: catalogCsvUrl. Колонки: id,name,description,price,image,available. Категорий нет. ID уникальный и постоянный, цена — число, image — имя файла, available — TRUE или FALSE. Строка с пустой доступностью считается неопубликованным черновиком. Для доступной начинки нужны все поля.

Изменения названий, описаний, цен и доступности читаются при открытии страницы без пересборки; Google может обновлять CSV с задержкой. Сервер проверяет начинку по тому же CSV. Для нового изображения добавьте файл в public/catalog/ и опубликуйте GitHub-изменение. catalogImageAliases сопоставляет image2.jpg…image5.jpg с предоставленными PNG, сохраняя оригиналы.

Логотипы: public/brand/. Фотографии работ: public/gallery/. Отзывы: public/reviews/. Их списки и ссылка Pinterest задаются в config.js. Отзыв открывается целиком нажатием на картинку. Галерея содержит собственные работы с доски Pinterest, предоставленной владельцем.

## Заказ и переписка

Форма сохраняет заказ и ставит уведомление владельцу в постоянную очередь. Клиент получает номер и одноразовую ссылку на выбранного бота на 30 минут. До Start аккаунт клиента не привязан, ответ в мессенджер невозможен; владелец видит оставленный телефон. После Start доступна карточка. Если мессенджер открыл чат без привязки, раскройте «В боте не появилась заявка?» на шаге подтверждения, скопируйте команду и отправьте её боту. Это тот же одноразовый код, срок не продлевается. Итоговую цену и возможность изготовления согласует кондитер. Старые обращения Telegram продолжают работать.

Владелец в каждом боте: /requests — фильтры, страницы по 8, карточка, история, ответ, «В работу», «Завершить». Ответ вводится именно ответом на ForceReply-подсказку. Клиент: /my — свои обращения, статус, история, «Написать уточнение». В MAX нужно зажать сообщение-подсказку на телефоне или нажать на него правой кнопкой на компьютере, затем выбрать «Ответить». Только после этого вводите текст. Обычное сообщение не будет отнесено к последнему открытому заказу. /id показывает только собственный ID; MAX ID не назначает владельца. /retry доступна владельцу соответствующего канала для ошибок доставки этого канала.

Статусы: draft, new, in_progress, done. Подтверждённые обращения и переписка автоматически не удаляются. Подсказки привязаны к каналу, chat_id и message_id; ответы по разным заказам не смешиваются. Таблицы защищены RLS, anon и authenticated не имеют прямого доступа. Миграции меняют только собственную схему requests_app.

## Обновление

Node.js 24: npm ci, npm run check, npm test, npm run bundle. npm run preview открывает http://127.0.0.1:8788 . Тесты используют PGlite с настоящими четырьмя SQL-миграциями и тестовыми транспортами. Workflow Checks проверяет GitHub; Cloudflare отдельно публикует public из main.

Обновление GitHub не разворачивает Edge Functions и не выполняет SQL. Миграции supabase/migrations применяются по порядку; 001, 002, 003 и 004 уже применены. npm run bundle готовит самостоятельные файлы в .local/dashboard для Supabase Dashboard Editor. При изменении общего серверного кода обновите все использующие его функции.

Рабочие функции: create-application, telegram-hook, max-hook. Их стандартная JWT-проверка отключена, предусмотрены собственные проверки: валидация и лимиты формы, секретный заголовок webhook Telegram или MAX. CORS принимает точный origin https://nevinnye-sladosti-orders.pages.dev и не заменяет авторизацию. Не ослабляйте защиту остальных ресурсов.

Секреты находятся в Supabase и игнорируемом .local/secrets.env: BOT_TOKEN, BOT_USERNAME, ADMIN_CHAT_ID, SITE_URL, TG_WEBHOOK_SECRET, FORM_SECRET, SETUP_SECRET, MAX_BOT_TOKEN, MAX_BOT_USERNAME, MAX_WEBHOOK_SECRET, MAX_ADMIN_CHAT_ID, GOOGLE_CATALOG_CSV_URL. Для RPC поддерживаются SERVER_DB_KEY, SUPABASE_SECRET_KEYS и SUPABASE_SERVICE_ROLE_KEY. Никогда не переносите серверные ключи в public, README или Git.

setup-telegram и setup-max нужны временно для подключения/восстановления; исходники сохраняются. node scripts/owner.mjs status|register|test и node scripts/max.mjs identity|status|register обращаются через Supabase с X-Setup-Secret из локального файла. После удаления временной функции скрипт недоступен до её повторного развёртывания. Не сбрасывайте накопленные updates. MAX transport проверяет TLS и дополнительно доверяет официальным сертификатам УЦ Минцифры только в своём HTTP-клиенте; глобальная проверка сертификатов не отключается.

## Проверка и восстановление

После серверного обновления проведите обозначенный контрольный заказ через опубликованный сайт: Start, карточка владельца, ответ на подсказку, получение ответа, история, уточнение и статус. Проверьте БД и состояния outbox. Двух реальных клиентов и телефон при выключенном компьютере владельца проверяют отдельно. Автотесты не заменяют живую проверку. Живой обмен Telegram → MAX и MAX → Telegram на контрольном обращении №4 проверен до переключения на раздельное управление. После изменения роли владельца проверены /requests, ответ, история, статусы «В работе» и «Завершена» в MAX. Новый контрольный заказ №5 отправлен через опубликованную форму: уведомление и подтверждение пришли в MAX. Два разных реальных клиента пока не проверялись.

Outbox постоянная: pending, processing, sent, failed, уникальные эффекты, попытки, lease_token, leased_until. Ошибка отправки не считается доставкой. После разблокировки бота используйте /retry. Истёкшие аренды восстанавливаются при следующем событии. Без событий фонового таймера нет. Содержимое переписки в журналы не выводится.

Бесплатные планы имеют квоты; Supabase может приостановить неактивный проект. После паузы восстановите проект в Dashboard и проверьте webhook. MAX может отключить подписку после длительных ошибок — тогда временно восстановите setup-max и зарегистрируйте её заново. Доступность зависит от сети. Авария между отправкой и фиксацией результата теоретически может дать повтор сообщения: абсолютная exactly-once доставка не обещается. Сохраняйте резервные копии схемы и проверяйте восстановление отдельно; реальные заявки при проверках не удаляйте.

Миграция 004 добавляет RPC nr_handle_event_v2 и nr_create_order_v2 с EXECUTE только для service_role. При пустом MAX_ADMIN_CHAT_ID сохраняется прежнее единое управление из Telegram. При заданном проверенном MAX_ADMIN_CHAT_ID списки, карточки и повтор доставки владельца ограничены своим каналом. Старые RPC оставлены для совместимости. Диагностические записи max-hook содержат только тип события, этап и булевы признаки; тексты, ID, заголовки и секреты в журнал не выводятся.

Временные функции setup-telegram и setup-max удалены из развёрнутого проекта после проверки; исходники и самостоятельные bundle сохранены. На 11.11.2026 рабочие функции отвечают отказом 401 без собственного секрета webhook, setup-max — 404. При проверке очередь не содержала failed/pending/processing. Главный экран использует предоставленное владельцем горизонтальное фото public/hero/celebration-wide.png: на компьютере — баннер во всю ширину с тёмно-синим заголовком слева; на телефоне — отдельное фото с кадрированием справа и текстом вне изображения.
